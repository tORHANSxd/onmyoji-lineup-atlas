# TA 阵容解析说明

本版依据用户指定任务 `01a093c9-4254-7980-ba58-9da498e7c913` 的研究成果：`onmyoji_ta.py`、`test_vectors.json`、`bytecode_evidence.txt`。本仓库不分发APK、游戏字节码或游戏登录凭据。测试夹具使用 `test-player`、`test-0` 等虚拟标识。

## 两种分享路径

`|TA|<share_key>` 是服务器分享键。v0.4.0 已接入研究任务实测成功的网易扫码协议：设备登记、手机确认、MPay 令牌兑换、`login_with_sdk`、角色选择，然后调用 `lineup_assisant_logic.get_share_lineup_data`。返回的 `lineup_data` 继续交给同一个本地解码器。无需在电脑启动完整游戏客户端；不能仅凭分享键离线还原。

v0.7.0 启动直接读取本地资料，扫码入口是独立页面，主动获取二维码。查看、管理、库存和备份可以离线使用；解析和服务器查询仍要求本次账号认证。解析落盘另外校验登录 epoch，退出后的迟到结果不能写回。本地管理保存不依赖登录。

登录模块随安装包提供，通过私有标准输入/输出管道与 Electron 通信，不监听本地 HTTP 端口。服务器分类、搜索、已有角色和角色名称来自官方目录及本次登录结果。只支持网易账号授权，目录中的其他渠道分类不表示已实现对应渠道登录。

批量查询复用同一角色的已认证游戏连接。角色切换、连接失败或空闲超过25秒时释放连接并在下一条重建；单次查询回包最多等待20秒。连接阶段有独立截止时间，外层165秒看门狗只兜底冻结子进程。网络或协议异常清理连接但保留有效登录令牌，记录原因后继续下一条；分享键匹配且错误码为整数的业务回包保留健康连接，不因一条过期码反复登录角色；认证失效须重新登录。退出或关闭应用释放套接字、子进程和内存凭据。

2026-09-12 本工具的冻结登录模块已真实扫码成功，读取到2个角色，并在服务器15012连续两次成功查询 `|TA|d902c7045f350394d41df622c66e398a`，结果为V3「个突/寮突」的6个位置。该验证发现并修复了旧研究代码的生命周期边界：`destroy_entity` 可能是账号对象释放，只有目标为当前角色的销毁才表示角色会话结束。只有 `err=0` 且分享键与本次输入完全一致的回包才可作为成功内容；非零业务码以结构化失败返回。

可导入自己取得的查询响应：

```json
{
  "err": 0,
  "share_key": "原始文字分享键，不含前缀",
  "lineup_data": "完整Base64内容"
}
```

如同时提供 `code`，它必须与 `share_key` 一致。没有分享键时只保存为自创二维码文本，不能自动关联某个短码。数组表示批量回包，解析全批成功后才合并保存。

`#TA#<payload>` 自创二维码的内容可直接在本机解码：严格Base64 → zlib → MessagePack整数键映射 → 按协议版本展开压缩字段。纯数字后缀是官方阵容编号，需要官方配置，不能当作压缩内容。

## 已实现的契约

- V0–V3、缺省版本V0；保留 `phconf` 和展开后的 `hconf`。
- 槽位、式神/阴阳师类型、技能ID/等级、觉醒、星级/等级、御魂字段、契灵、AI技能、最高属性、分数、实例ID与扩展字段。
- MessagePack中的BSON扩展42/43/44；ObjectId 支持12字节二进制与24位大小写ASCII十六进制文本，统一保存小写hex，拒绝非hex和高位字节。时间保留微秒精度，二进制采用显式Base64对象保存。
- 最大输入32 MiB、最大解压16 MiB；拒绝截断、zlib尾随内容、未知版本、错位槽位及非整数顶层字段。
- 12组参考向量分别覆盖各版本的常规样本、扩展字段和null字段。另有损坏输入、关联不符、解压限额和合并保留元数据测试。

V1–V3按其字段结构判断角色类型。V0有御魂/契灵配置时可区分；空配置需要完整且经过核验的阴阳师ID表，现有资料不足时拒绝猜测。当前已对应晴明10、神乐11、八百比丘尼12、源博雅13、源赖光15、藤原道长16；未知ID不会猜测映射。独立解析函数支持调用方显式传入 `yysIds`，普通界面不接受未经核验的自动映射。

## 解析与计算的边界

v0.5.0对照用户提供的2.8.84 APK静态数据与计算逻辑，落实了 `criteria`、`two_suit`、`limit`、`highest_limit` 的已支持语义。内部主属性位置1/3/5对应实际2/4/6号位；重复套装数量相加，属性两件套是指定套装之外的额外要求；暴击、暴伤、命中、抵抗的范围按百分数换算。详见 [御魂计算口径](SOUL_CALCULATOR.md)。

原始字段始终保留。阴阳师／英杰、契灵、术印仅展示，不参与账号核对、缺口标签和排序。式神 AI 技能、保留当前穿戴等不能由库存证实的条件仍单列核对项；协议解压成功不代表游戏实战已经满足。旧版已保存 TA 内容在本机重新映射为新版条件，无需为映射升级重复查询。

登录选定已有角色后，自动扫描未解析原码，按码去重并逐条查询。查询起点至少间隔1.5秒，手动重复同码冷却60秒（从最后一次尝试计）；成功结果逐条落盘。只有分享键匹配的90011「请稍后再试」会在本次任务中等待3秒、6秒各重试一次，总计最多3次，并让后续原码遵守这次退避。31279「文字码已过期」不自动重试；网络异常、未知错误和错配回包也不自动重试。以上间隔为本工具的保守策略，并非已核验的服务器限流阈值。用户暂停保留既有成果，单条失败/限流记录原因并继续其余原码；注销或切换角色取消排队任务，退避等待每250毫秒检查会话，旧会话迟到结果不可提交。失败记录保留错误分类、服务器代码和尝试次数；保存失败则暂停以保护本地成果。已有本地解析结果可以直接查看，用户显式重新解析才重新请求。

二维码的作者/实例标识属于原始内容的一部分，完整JSON导出会保留。请仅分享自己允许公开的阵容资料。

## 副本与素材

`select_stage_id` 是原码自带副本选择 ID。已按 APK `ta_stage`（entry20626）与 `ta_stage_tag`（entry20602）建立 686 条唯一关卡路径，记录于 `data/stages.json`。默认使用解析关卡细分首领、难度和层数；明确手工分类优先。Excel 泛分类与关卡一致时用关卡补细，有明确冲突时保留来源的实际用途，同一码的多个来源用途各自保留。七条拾光永恒码在来源中可确认属于短线、困难或探索遭遇战，其第一章占位 ID 在 `app/categories.js` 按原码修正；其他第一章码不作推断。原始关卡保留于 `decodedStage`，不改写协议数据。

浏览路径包含 `category`、`subcategory`、可选 `section` 和 `dungeon`。逢魔统一为日常 → 逢魔 → 类型 → 首领；真蛇跨列御魂和周常，彼世跨列日常逢魔和周常。分类筛选和候选搜索按整条路径匹配，避免同码多个路径的字段交叉拼接。首页逐级预览，完整路径或常用别名可直接搜索到最细分类，记录总数按阵容去重。浏览分组不代表实时开放时间表。

映射版本 4 的要求完整性只统计式神侧协议字段；旧版 v3 中仅由主角字段造成的未知状态也会在计算时排除，式神侧未知条件仍保留。主角 ID、副本字段和原始 payload 不变，无需为升级重新请求服务器。
