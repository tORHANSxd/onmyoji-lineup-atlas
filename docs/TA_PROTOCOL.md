# TA 阵容解析说明

本版依据用户指定任务 `01a093c9-4254-7980-ba58-9da498e7c913` 的研究成果：`onmyoji_ta.py`、`test_vectors.json`、`bytecode_evidence.txt`。本仓库不分发APK、游戏字节码或游戏登录凭据。测试夹具使用 `test-player`、`test-0` 等虚拟标识。

## 两种分享路径

`|TA|<share_key>` 是服务器分享键。游戏客户端通过现有游戏会话调用 `lineup_assisant_logic.get_share_lineup_data`，参数为 `{share_key}`，并使用返回的 `lineup_data`。这不是已发现的公开HTTP接口；本程序没有游戏会话接入，也不能仅凭分享键还原成员。

可导入自己取得的查询响应：

```json
{
  "err": 0,
  "share_key": "原始文字分享键，不含前缀",
  "lineup_data": "完整Base64内容"
}
```

如同时提供 `code`，它必须与 `share_key` 一致。没有分享键时只保存为自创二维码文本，不能自动关联某个短码。数组表示批量回包，解析全批成功后才合并保存。

`#TA#<payload>` 自创二维码的内容可直接在本机解码：严格Base64 → zlib → MessagePack整数键映射 → 按协议版本展开压缩字段。纯数字后缀是官方阵容编号，需要官方配置，不能当作压缩内容。

## 已实现的契约

- V0–V3、缺省版本V0；保留 `phconf` 和展开后的 `hconf`。
- 槽位、式神/阴阳师类型、技能ID/等级、觉醒、星级/等级、御魂字段、契灵、AI技能、最高属性、分数、实例ID与扩展字段。
- MessagePack中的BSON扩展42/43/44；时间保留微秒精度，二进制采用显式Base64对象保存。
- 最大输入32 MiB、最大解压16 MiB；拒绝截断、zlib尾随内容、未知版本、错位槽位及非整数顶层字段。
- 12组参考向量分别覆盖各版本的常规样本、扩展字段和null字段。另有损坏输入、关联不符、解压限额和合并保留元数据测试。

V1–V3按其字段结构判断角色类型。V0有御魂/契灵配置时可区分；空配置需要完整且经过核验的阴阳师ID表，现有资料不足时拒绝猜测。目前仅核实晴明ID10，其他主角ID仍显示原始编号。独立解析函数支持调用方显式传入 `yysIds`，普通界面不接受未经核验的自动映射。

## 解析与计算的边界

协议解压成功代表读出了保存内容，不代表御魂业务语义或战斗规则已经全部确认。`criteria`、`two_suit`、`limit`、`highest_limit`、契灵和AI等原始信息可查看。尚未完成游戏计算逻辑核对的部分保留待核对状态，不会转成猜测阈值并用于“配置可组成”的断言。

二维码的作者/实例标识属于原始内容的一部分，完整JSON导出会保留。请仅分享自己允许公开的阵容资料。
