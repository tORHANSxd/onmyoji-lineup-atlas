# 御契 v0.7.0 修订与验收

本次是本地开发构建，没有发布新的 GitHub Release。历史 Release 已按用户要求清理，只保留原有的 v0.6.0 预发布版；Git 标签和提交历史保留。

## 批量解析

旧实现有两项已证实的问题：每条原码重新建连并完成角色登录，批量还会在连续失败后停止。新实现复用同角色有效连接，成功逐条保存，非致命失败记录后继续。查询等待最多20秒；角色切换、异常及连接空闲时释放旧套接字。外层子进程看门狗用于处理底层冻结，不作为正常逐条查询时限。

查询仍串行，起点最小间隔0.8秒，同一原码冷却60秒。没有通过并发冲击服务或无限重试提速。登录失效和本地保存失败会明确暂停，避免写入失效会话或丢失成功内容；修复后从剩余条目继续。

本次未取得用户实际第46条的服务端错误回包，不能断言该原码本身损坏。回归特意设置第46、47、48条连续失败、第91条超时和第155条失败，验证最终150成功、5失败，不在46条停住。真实155条在线查询仍需用户本次扫码后的游戏会话。

## 阵容与界面

- 离线启动，独立扫码页面；解析前登录提醒。改名后固定使用原 `onmyoji-lineup-atlas` 用户数据目录。
- 阵容库管理支持原码、名称、分类、备注编辑；修改原码清除旧解析结果，管理信息修改不改写解码配置。
- 以原码 `select_stage_id` 映射副本，内置686条 APK 关卡事实；顶层日常/周常/常驻为互斥管理分组，逐级筛选。
- 六成员卡片按两列纵向排列，小窗口改为单列。每个式神六个御魂位置可以点击；缺口放在对应技能、位置和面板旁。
- 缩略卡给出式神、技能、培养、御魂等缺口类型。删除式神图鉴页及账号计算器入口，计算与补强建议集中到阵容。
- 御契名称、原创logo、窗口图标、快捷方式和安装器品牌统一；本地素材来源与哈希可查。

## 精算与补强

使用完整库存的分支定界搜索，按成员顺序的原码指标向量求字典序最优。无时间或候选截断充当证明；计算中保留候选，暂停恢复保留本次进程内搜索栈。同队式神和御魂实例不重复，阵容之间独立使用库存。

基准还发现并修复 `涅槃火 / 涅槃之火` 名称不一致，原本会让实际库存被错误归为未知套装。证明要求单调指标上界所需的数据有效，未知字段或缺失数据不会转成无解结论。

主角、契灵、穿戴归属和战斗设置未包含于当前平安志导出，故不能宣称完整游戏阵容已经验证。式神御魂可有独立证明，整体仍显示其他条件待核对。无解的诊断候选不是全局最小补强证明，也不代表只有一种补法。

建议优先利用现有合格库存及兑换资源；主属性/星级不能靠普通强化改变，已强化等级不能下调。主属性错误、套装冲突或面板超上限时，不优先强化当前胚子。分段强化检查随机副属性；不承诺指定兑换位置/主属性或随机强化必定命中，不虚构官方消耗数字和成功概率。
